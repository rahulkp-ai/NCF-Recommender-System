# `research/`

Independent research environment for developing and evaluating the
recommendation models. **Never imported by production code** — see
`ARCHITECTURE.md` and `docs/decisions/0001-research-production-separation.md`
(with one known, documented exception — see "Boundary note" below).

## Structure

- `datasets/` — raw (MovieLens-1M `.dat` files + original `.zip`/`README`)
  and processed (train/val/test splits, popularity/content engine
  pickles) data. Renamed from `data/` in Phase 4 to avoid a naming
  collision with `production/artifacts/`.
- `notebooks/` — the numbered notebook sequence (`01_ncf_formulation` →
  `05_hybrid_test`) telling the research story in order, plus their
  supporting `figures/`.
- `models/` — three implementations, each a genuinely different
  approach, not variations of one thing:
    - `scratch_ncf/` — NCF built from first principles in NumPy
      (custom embeddings, forward pass, loss, optimizer)
    - `pytorch_ncf/` — the same architecture in PyTorch, for the speed/
      parity comparison that's this project's central experiment
    - `hybrid/` — collaborative (NCF) + content + popularity blending,
      plus cold-start handling. Production has its own hardened,
      since-split copy — see `docs/decisions/0002` and `0003`.
- `evaluation/` — metrics (`metrics.py`), plotting (`plots.py`),
  training logs (`*_log.json`), trained weights
  (`scratch_ncf_weights.npz`, `pytorch_ncf_weights.pt`), the
  scratch-vs-pytorch comparison script (`compare.py`,
  `comparison.json`), `benchmark_summary.ipynb`
- `comparisons/` — a small FastAPI router (`api/compare.py`) + static
  dashboard (`dashboard/index.html`) that serve `evaluation/comparison.json`
  for interactive viewing. Distinct from `evaluation/compare.py`, which
  _generates_ that JSON from the training logs — one produces the data,
  this one presents it.
- `archive/` — superseded material kept for history rather than deleted
  (e.g. `early_drafts/` — draft notebooks that were rewritten into the
  polished `notebooks/` sequence).
- `tests/` — tests for research code (gradient checks on the from-scratch
  implementation).
- `requirements.txt` — research's own dependency set, independent from
  `production`'s (see `ARCHITECTURE.md`).

## Why two figure sets (`evaluation/figures/paper/` vs `.../thesis/`)

Checked via checksum before organizing — they are **not duplicates**,
they're different renders of related results for two different
documents: `figures/paper/` (`fig1`–`fig4`) is generated by
`evaluation/plots.py` for the IEEE paper (`ieee/`); `figures/thesis/`
(`figure_4_1`, `figure_4_2`) is generated by
`notebooks/04_pytorch_comparison.ipynb` for the thesis (`thesis/`,
chapter 4 — hence that numbering). Both generators' save paths were
updated in Phase 6 to write into the new subfolders.

## What this project does _not_ include (documented, not silently absent)

No hyperparameter search and no formal ablation study were run — the
scratch-vs-PyTorch comparison is a parity/speed study at fixed
hyperparameters, not a search over them. `research/models/*` each train
with one fixed configuration. If this changes, a `research/experiments/`
or `research/hyperparameter_search/` folder would be the right place for
it — not scaffolded preemptively (same principle as
`docs/decisions/0004-deferred-enterprise-patterns.md`).

## Boundary note

`production/tests/unit/test_metrics.py` imports
`research.evaluation.metrics` directly — a research → production
import that technically violates the rule this README states above.
This is a known, tracked exception (not a silent violation) — see
`docs/decisions/0001-research-production-separation.md` and the Phase 4
`MIGRATION_LOG.md` for how it was found and why it's still open.

## Setup

```bash
cd research
pip install -r requirements.txt
jupyter lab
```

## Promoting a trained model to production

Currently manual (copy `evaluation/`'s weights + `datasets/processed/`'s
engine pickles into `production/artifacts/`) — a `scripts/export_model.py`
bridge is planned, see `ROADMAP.md`. Until then, re-run
`evaluation/compare.py` and check `benchmark_summary.ipynb`'s numbers
before promoting a new checkpoint.
